# API接口设计规范.md

> 责任部门：架构组
> 生效口径：自 2026-01-01 起按本文件执行；与法律法规冲突时以法律法规为准。

## 1. 使用边界

规范统一资源命名、HTTP 语义、幂等、分页、错误响应、鉴权和版本演进，使调用方可以稳定自动化集成。

接口设计应统一资源模型、鉴权方式、错误响应和版本策略，确保调用行为稳定且变更影响可控。

所有申请、复核和例外均须使用公司工单、OA 或指定业务系统留痕，口头同意不能替代正式审批。

## 2. 实施责任

| 角色或对象 | 主要责任 | 不得替代的控制 |
|---|---|---|
| 申请人/执行人 | 提交真实完整资料并按批准范围执行 | 不得自行批准本人申请 |
| 直属负责人 | 核实业务必要性、资源与人员安排 | 不得跳过架构组专业复核 |
| 架构组经办人 | 校验材料、标准、风险与系统记录 | 不得同时承担最终批准 |
| 架构组负责人 | 审批高风险事项并处理升级 | 不得删除或弱化审计记录 |
| admin | 仅按管理员职责维护权限和审计能力 | 不因技术权限替代业务审批 |

## 3. 实施规则

### 3.1 规则 1

REST 路径使用复数名词和小写连字符，不得在路径中出现 create、get 等动作词。

执行证据应关联文档编号、申请人、审批人、时间戳和结果；缺少任一关键字段时状态保持为“待补充”。

### 3.2 规则 2

写操作必须定义幂等策略；支付、发券等关键接口使用至少 24 小时有效的幂等键。

执行证据应关联文档编号、申请人、审批人、时间戳和结果；缺少任一关键字段时状态保持为“待补充”。

### 3.3 规则 3

列表接口默认页大小 20，最大 100；不得通过无限制 page_size 导出全量数据。

执行证据应关联文档编号、申请人、审批人、时间戳和结果；缺少任一关键字段时状态保持为“待补充”。

### 3.4 规则 4

错误响应必须包含稳定 code、可读 message 和 request_id，禁止将堆栈或数据库语句返回客户端。

执行证据应关联文档编号、申请人、审批人、时间戳和结果；缺少任一关键字段时状态保持为“待补充”。

### 3.5 规则 5

删除字段或改变语义属于破坏性变更，须发布新主版本并提供不少于 90 日迁移期。

执行证据应关联文档编号、申请人、审批人、时间戳和结果；缺少任一关键字段时状态保持为“待补充”。

## 4. 质量门槛

| 触发条件 | 控制标准 | 审批或处置责任 |
|---|---|---|
| 列表默认页大小 | 20 条 | 接口作者 |
| 列表最大页大小 | 100 条 | API 网关强制 |
| 破坏性变更 | 至少 90 日迁移期 | 架构负责人 |
| 公网接口 P95 延迟 | 目标不超过 500 ms | 服务负责人 |

数字区间按“含下限、含上限”解释；同一事项同时命中多项条件时，执行更严格的一项。

## 5. 落地顺序与授权控制

1. 接口作者编写消费者场景、数据分类和非功能指标。
   - 本节点完成后由系统记录办理人、完成时间、附件版本和下一责任人。
2. 按照 OpenAPI 描述请求、响应、错误、鉴权和示例。
   - 本节点完成后由系统记录办理人、完成时间、附件版本和下一责任人。
3. 领域评审人检查资源模型、边界和向后兼容。
   - 本节点完成后由系统记录办理人、完成时间、附件版本和下一责任人。
4. 安全评审验证授权、限流、输入校验和敏感字段。
   - 本节点完成后由系统记录办理人、完成时间、附件版本和下一责任人。
5. 契约测试通过后发布到接口目录并监控错误率和延迟。
   - 本节点完成后由系统记录办理人、完成时间、附件版本和下一责任人。

### 使用示例

- 合规示例：接口作者编写消费者场景、数据分类和非功能指标。随后核对“列表默认页大小”，并按“20 条”留存证据。
- 不合规示例：未执行“REST 路径使用复数名词和小写连字符，不得在路径中出现 create、get 等动作词。”且没有申请例外，即直接进入后续操作。
- 修正方式：停止未批准动作，由架构组复核影响范围，补齐记录后从失败节点重新开始。

### 禁止事项

- REST 路径使用复数名词和小写连字符，不得在路径中出现 create、get 等动作词。
- 列表接口默认页大小 20，最大 100；不得通过无限制 page_size 导出全量数据。
- 错误响应必须包含稳定 code、可读 message 和 request_id，禁止将堆栈或数据库语句返回客户端。

### 审批结论规则

- 通过：材料齐全、预算或资源已落实、风险在批准范围内。
- 退回：字段、凭证、评估或前置审批不完整，补充后重新计时。
- 拒绝：违反禁止性规定、超出授权边界或无法形成有效控制。
- 条件通过：仅适用于可在明确期限内补正的低风险事项，必须写明条件和到期日。

## 6. 违规处理

- 情形 1：法律要求立即停止返回某敏感字段。
  - 处置要求：由架构组经办人记录原因、临时措施、恢复期限和复核人。
- 情形 2：关键漏洞要求在迁移期内变更鉴权。
  - 处置要求：由架构组经办人记录原因、临时措施、恢复期限和复核人。
- 情形 3：第三方遗留协议无法使用标准 HTTP 语义。
  - 处置要求：由架构组经办人记录原因、临时措施、恢复期限和复核人。

任何紧急处置均不得删除原始记录；先行处理的事项须在 24 小时内补齐审批，逾期自动升级至责任部门负责人。

## 7. 记录与检查清单

业务记录保存期限不少于3 年；涉及诉讼、审计或调查的，保存至相关事项结束后再计算期限。

| 检查项 | 合格标准 | 不合格处理 |
|---|---|---|
| C01 | 确认“REST 路径使用复数名词和小写连字符，不得在路径中出现 create、get 等动作词。”已有系统记录或书面凭证。 | 退回责任人补正并记录复核结果 |
| C02 | 确认“写操作必须定义幂等策略”已有系统记录或书面凭证。 | 退回责任人补正并记录复核结果 |
| C03 | 确认“列表接口默认页大小 20，最大 100”已有系统记录或书面凭证。 | 退回责任人补正并记录复核结果 |
| C04 | 确认“错误响应必须包含稳定 code、可读 message 和 request_id，禁止将堆栈或数据库语句返回客户端。”已有系统记录或书面凭证。 | 退回责任人补正并记录复核结果 |

### 抽查频率

- 架构组每季度至少抽查 1 次，样本不少于当季事项的 10%，且不少于 5 单。
- 涉及金额、生产系统、个人敏感信息或对外承诺的事项，纳入 100% 复核范围。
- 连续 2 次抽查发现同类缺陷时，责任团队须在 10 个工作日内提交整改计划。

## 8. FAQ

### FAQ-001：最关键的时限或额度如何判断？

先核对量化标准表。对于“列表默认页大小”，必须执行“20 条”，不得以口头说明放宽。

### FAQ-002：谁可以作出最终批准？

按审批节点逐级处理；达到高风险或升级条件时，由架构组负责人或表中指定批准人作出结论，admin 不替代业务批准。

### FAQ-003：材料不完整是否可以先办理？

原则上不可以。仅当出现“法律要求立即停止返回某敏感字段。”且延迟会扩大损失时，方可先采取可逆措施，并在 24 小时内补齐审批。

### FAQ-004：同一事项命中多个标准怎么办？

执行审批层级更高、时限更短或控制更严格的标准，并在申请单中记录命中条件。

### FAQ-005：记录到期后能否直接删除？

不能。达到3 年保存期后仍须先确认不存在审计、争议、诉讼或调查保全要求，再按数据销毁流程审批。
